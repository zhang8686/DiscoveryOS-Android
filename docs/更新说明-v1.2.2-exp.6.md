# DiscoveryOSX v1.2.2-exp.6（实验包）

**这一版把「选字」还给正文本身：不再换输入框，长按就是系统在正文上选词。**

## 1. 根因：一直在用第二个渲染器对齐第一个

前几版的做法是：长按正文 → 把这一楼换成一组「只读输入框」，再由输入框自己的字号、字重、行距去模仿正文。这条路注定对不齐，因为**画字的是两套东西**：

| | 正文 | 选字态（旧） |
|---|---|---|
| 排版器 | `TextView`（nsh-base 的文本视图，块 + 块前间距 + 引用竖线） | 原生 `EditText`（一种字号、一种字距、一种行高） |
| 段间距 | 块前 11.25pt / 标题按自身字号算 0.6、1.1、1.6、1.4 倍 | 只能用外边距近似 |
| 分段 | 整篇一个视图 | 一段一个输入框（所以选区跨不过段） |
| 高度 | 由排版算 | 由输入框自己算（多一行就多一截空白） |

只要有两套渲染器，字体回退、`letterSpacing` 的取整、行高取整、字体 padding 这几处就总会差一点；「完全一致」在这条路上不可能做到。这也是为什么行距改了四版还在差：**问题不在参数，在架构**。

## 2. nsh nightly 已经给了正解：`selectable`

最新 nightly（我们打包用的 `589a60f`，2026-11-23）里，`TextView` 的根视图本身就是一个 **selectable view**（`crates/nsh-base/src/text_view/view.rs`：`view().flex_col()…selectable(props.selectable)`），文档写的是「its texts share one selection, block to block」。Android 端的实现在 `SelectableView.java` + `TextBox.java`：

- 长按 → `BreakIterator` 选中手指下的**词**（带长按震动）；
- 两端手柄拖动 → 命中测试取字符偏移，**逐字**增减；
- 跨块/跨段 → 选区模型在 Rust（`nsh-core` 的 selection），一块接一块地算，复制时按阅读顺序拼接；
- 浮条 → 系统 `ActionMode`：复制、全选、分享；
- 点正文以外、或复制之后 → 系统自己收起选区。

也就是说：**正文不用换、不用复制一份、不用第二套渲染器**，选字就发生在正文上。视觉上不存在「切换」，字体、字号、行高、段间距、引用竖线与缩进、边距、对齐、换行规则全部是同一份排版的结果。

> 关于 v1.1.9 那次「只能整行整段」：当时用的是更早的运行时，选区是按块各自成立的（旧文档的原话是 “each block on its own”），手柄拖不出当前段；块与块合成一条选区正是后来 nightly 补上的能力（`continues` + 区域选区模型）。这一版用的就是补上之后的运行时。

## 3. 修改范围（只动选字这一处）

- `src/ui/Thread.tsx`
  - 正文 `TextView` 由 `selectable={false}` + 外层 `onLongPress` 换状态，改为 `selectable={true}`；
  - 删除 `inlineSelect` 状态、`endInlineSelect`、`BackHandler` 的选字拦截、标题栏与楼层行的「点一下结束选字」回调，以及正文的三元切换；
  - 选区颜色由 `classes={{ root: "selection:bg-blue-500" }}` 改为 `styles.root.selectionColor: "#4285F4"`（系统蓝，和以前一致）；
  - 正文的 `styles`（字号、行高、首帖标题 16pt/500）、`extensions`、`renderCustom`、`onImagePress`、`onLinkPress` 全部原样保留。
- 删除 `src/ui/InlineTextSelect.tsx`、`inlineSelectHarness.tsx`、`inlineSelect.test.ts`。
- `src/discuz/parse.ts` 的 `htmlToBlocks` 保留（纯解析函数，带单测），本次不再被 UI 使用。
- 运行时、图片调度、折叠手势、其余页面没有任何改动。

## 4. 验证要点

自动化：`nsh check` 通过；`nsh test` **162/162**（删掉了随输入框方案一起下线的那 6 项，其余全绿）。

真机上请按这几条看：

1. 长按正文 → 手指下那个词被选中，出现两端手柄与系统浮条；**正文字号、字重、行距、段间距、引用竖线位置一个字都不动**。
2. 拖手柄跨过段落边界 → 选区连续延伸（这是上一版做不到的）。
3. 复制 → 文字进剪贴板，选区与浮条由系统收起，正文还是正文（没有「恢复」动作，因为从未被替换）。
4. 点正文以外 → 选区消失，页面点击、滚动正常。
5. 图片、链接、引用箭头仍按原来的逻辑响应（单击）。
6. 楼层高度在长按前后完全不变，不会多出空白行。

## 5. 回退

若某台设备上系统选区的观感或手势不符预期：装回 `DiscoveryOSX-V1.2.2-exp6-release.apk`（exp.5，versionCode 65）即可恢复输入框方案；两者同钥匙签名，可直接覆盖。
