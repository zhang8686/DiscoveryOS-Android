# DiscoveryOSX v1.2.2-exp.5（实验包）

**这一版把整个运行时换成了最新 nsh nightly（2026-11-23，`589a60f`）自己编译的一份**（`libnsh.so` 44.1 MB 与 `classes.dex` 570 KB），CLI、运行时、源码三者同一个版本，请当作实验包。

## 1. 图片查看器手势：这一版修的是「版本不同源」

上一版的问题不在应用代码里——`imageViewer.tsx` 一个字符都没改过。真正的原因是我编译运行时用的源码和**正式版包里那份运行时不是同一支**：

| | 正式版（v1.2.1）运行时 | 上一版实验包运行时 |
|---|---|---|
| 触摸分发 `TouchTracker` | 没有边缘激活（`decideActivation` / `mayActivate`） | 有，且带 gate 判定 |
| 图片视图 `ImageBox` | 没有自己的 `dispatchTouchEvent` | 有，会先接一层触摸 |

也就是说上一版给用户装的运行时比正式版**新了一个分支**：那支里图片视图自己接管了一次触摸分发，于是查看器里的左右翻页、下滑关闭就摸不到了。

这一版把整条链换成官方最新 nightly 的同一份源码（`589a60f`，2026-11-23）：CLI、`classes.dex`、`libnsh.so` 全部由它编译（导出的 95 个 JNI 方法与该版官方运行时**完全一致**），除下面两处行距补丁外没有别的改动。

## 2. 行距：不再猜，改成「按正文的块逐个复刻」

前面几版都只对齐了「行高一个值」，所以只对了纯文本段落，其余全错。这次先去量了正文自己的排版（在测试宿主里逐类渲染对比），再按它的规则铺：

正文（`nsh-base` 的 TextView）实际的几何是：

- 块与块之间：`BODY_SIZE × 0.75` = **11.25pt**；
- 标题的行高按**它自己的字号**算，不是按应用给的字号：h1 = 27×1.25 = **33.75**、h2 = 20×1.35 = **27**、h3 = 17×1.35 = **22.95**；字距分别是 −0.02 / −0.012 / −0.012 em；标题上方的空间是「字号 × 1.1（前面是标题时 0.6，h2 1.6、h3 1.4）」；
- 引用（`[quote]` / `<blockquote>`）：左边 2pt 竖线 + **13.5pt** 缩进，文字用 80% 明度，内部段距还是 11.25pt。

选字态现在按这些数字铺：**每个段落、每个标题、引用里的每一段，各是一个输入框**，各自带字号、字重、字距与行高，块前留出正文的间距，引用整组套一条竖线并缩进。

实测对照（同一段 HTML，正文 vs 选字态，宽度 288）：

| 文档 | 正文高度 | 选字态高度 |
|---|---|---|
| 标题 + 两段正文 | 103 | 103 |
| 正文 + 两段引用 + 正文 | 126 | 125 |
| 正文 + h2 + 正文 | 116 | 117 |

差 1pt 是像素取整。

## 3. 行高真的落到每行了

标题块能拿到 33.75 这个行高，靠的是运行时新加的一处：

- 应用把该块的 `lineHeight` 交给输入框（`style.lineHeight`）；
- `InputBox.applyLineHeight()` 用**字体度量**（ascent→descent，已关字体 padding）算出差值，`setLineSpacing` 加到每一行；
- 只对只读输入框生效，且只有应用给了行高才动；普通输入框行为不变。

## 4. 图片显示更快（沿用上一版，清晰度不变）

只动调度，没动地址、没动请求尺寸：运行时下载池 4→6、应用预热并发 3→6、进帖预热 12 张、列表预取 8 张、进帖时先清列表遗留队列。

## 已知限制

- **选区不能跨段**：一个输入框只装一段（引用里的一段也算一段），跨段选取会先收起当前段。这是「一个输入框只有一种版式」的必然结果。
- 帖子里的 `[size=…]` 局部放大文字，在选字态回到该段自己的字号。
- 含图片的楼层进入选字后只剩纯文本（图片不显示），既有行为。
