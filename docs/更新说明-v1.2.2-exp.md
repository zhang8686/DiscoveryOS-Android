# DiscoveryOSX v1.2.2-exp.2（实验包）

这一版只为一件事存在：把实验包里两处没做对的地方改对。**它替换了框架运行时本身**（`libnsh.so` 与 `classes.dex` 都由本机从 nsh 0.6.0 源码重新编译），所以请把它当作实验包，不要当作日常版本。

## 1. 选字后与正文完全一致（上一版做反了）

上一版进入选字后，标题那几行**变小、变细、行距也变紧**。原因有两层：

- 首帖开头的标题在正文里是 16pt、字重 500，而选字块一律按正文的 15pt、400 排——所以一进选字，标题就缩了一号、细了一档。
- 字号变小后每行装得下更多字，折行行数少了，行距那一步算出来的差值超出护栏，于是退回系统默认行距（比正文紧）。

这一版的做法：选字块不再是一整块，而是按正文自己的分段来排——标题段单独一块（16pt / 500），其余是正文块（15pt / 400），两块首尾紧贴、中间不加任何空隙（`</h1>` 原本就只是一个换行）。行距那一步也改了取高度的来源：用输入框自己实到的高度，而不是等布局传进来的内容框，避免取不到值时整段不生效。

- 试验点：长按首帖，标题的字号、粗细、行距、换行位置都应与原文一模一样；楼层高度不变，退出后不跳。
- 已知限制：两块各自独立，选区不能跨过标题与正文之间那一条（跨块选择会先把上一块收起来）。

## 2. 左滑折叠：手势重新可用

上一版给折叠手势加了一个「窗口宽度 ≥ 900pt 才响应」的门槛，结果把竖屏首屏（约 400pt 宽）整段挡住——原来能用的右滑也一起失效了。

这一版把门槛从判断里拿出来，只放在横屏并排两列那一处（那里窗口太窄时本来就只能是图标栏，滑动没有可展示的效果）。竖屏「板块 + 列表」那一层不受宽度限制：右滑展开折起的板块栏，左滑把它收回成图标栏。

- 手势：横向 60pt 以上，或速度 700pt/s 以上才算数；竖直超过 10pt 交还给列表滚动。
- 覆盖两处：竖屏 3-2-1 阶梯里的「板块 + 列表」层，以及横屏/宽窗口并排的两列（右侧正文栏不受影响）。

## 回退

源码改动在仓库的这次提交里。装回 v1.2.1 即可回到正式版运行时；运行时两处（`InputBox.fitLines` 的三处调用、`InlineTextSelect` 的填满与分块）去掉即回到原样。
