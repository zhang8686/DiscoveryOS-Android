# DiscoveryOSX v1.2.1 更新说明

发布时间：2026-11-23

这一版只动选字时的样子：把多出来的提示行去掉，并让进入选字前后楼层的高度保持一致，正文不再被挤动。

## 一、选字状态不再显示底部提示行

长按正文进入选字后，正文下面原来还有一行「长按选词，拖两端手柄逐字选；点浮条「复制」后自动恢复正文」。这一行已删除。

- 选字状态下正文后面不再有任何附加文字。
- 长按选词、拖两端手柄逐字选、点浮条「复制」后自动恢复正文，行为都不变。

## 二、进入选字时楼层高度不变

进入选字时，楼层高度仍由一份看不见的正文文本撑住：它用正文的字号与行距排版，宽度也一样，所以折行位置与原正文一致，楼层多高、在哪里换行都保持原样。

- 输入框画在这份文本之上，不参与高度计算，所以整层不会被撑高或压扁。
- 下方内容不会被挤动，退出选字也不会有回弹。

## 三、最后一行下面不再堆空白

输入框显示文字用的是系统自己的行距，与正文设置的 1.5 倍行距不一定相同（多数机型上略紧）。以前把输入框拉满整层高度，多出来的空间全落在最后一行下面，看起来像一大块空白。

现在输入框只占它自己文字的高度，并在原高度里居中：多出来的空间上下均分，最后一行下面不再有一块空的。

## 四、关于输入框行距的说明

Android 的原生输入框（`EditText`）行距由系统字体度量决定，框架只给输入框设字号、不设行距，应用层没有可用的开关。因此选字时的行距是系统输入框自己的行距（约字号的 1.2 倍），与正文的 1.5 倍并不完全一致——这是这一版唯一没能做到「与正文完全一致」的地方。

要做到完全一致，只能改框架运行时本身（给输入框加上行距设置），那需要重编运行时并逐台验证，风险与工作量都远大于这次改动，暂时没有动。

## 五、保持不变

- 长按正文 → 长按选词 → 拖两端手柄逐字增减，句中任意位置可选。
- 浮条点「复制」→ 文字进剪贴板，选区收起，正文立刻恢复。
- 点正文以外的地方、或按返回键，同样可以退出选字。
- 手柄与选中底纹为系统蓝（`#4285F4`）。

## 安装说明

- 包名 `com.Android.DiscoveryOSX`，版本 1.2.1（versionCode 60）。
- 签名与 v1.1.6 – v1.2.0 相同，**可直接覆盖升级**。
- v1.1.0 用的是另一份证书，需先卸载再安装。
